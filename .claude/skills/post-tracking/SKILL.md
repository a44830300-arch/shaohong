# 게시글 올린 뒤 분석 (2026-11-26 강정준비준 요청)

## 언제 보나 (게시 시각 기준 8번)
1시간 · 2시간 · 3시간 · 24시간 · 48시간 · 72시간 · 1주(168시간) · 2주(336시간)

## 지켜야 할 것 (읽기만)
- 크리링이 **강정준비준의 크롬(Claude in Chrome)** 으로 들어가서 본다. 크리에이터 센터는 나들로그로 로그인돼 있다.
- **보기만 한다.** 올리기·고치기·지우기·좋아요·저장·댓글·답글·DM·팔로우를 하지 않는다. 데이터 내보내기(파일 다운로드)도 누르지 않는다.
- 한 번 볼 때 필요한 화면만 한 번씩 연다. 새로고침을 반복하거나 다른 사람 글을 긁어 오지 않는다. 정해진 8번 밖에는 알아서 들어가지 않는다.
- 로그인 화면·본인 확인·경고 창이 뜨면 아무것도 누르지 말고 강정준비준에게 알린다. 비밀번호는 넣지 않는다.
- 다른 계정(제주라이브)은 로그인을 바꾸지 않는다. 그 계정 글이면 강정준비준에게 로그인해 달라고 한다.

## "게시글 올렸어"라고 하면
1. `https://creator.rednote.com/statistics/data-analysis`(데이터 → 内容分析)에서 새 글의 제목과 게시 시각을 확인한다. 아직 안 나오면 `https://creator.rednote.com/new/note-manager`(笔记管理)에서 확인한다.
   - 두 화면의 시각이 1시간 다르게 보인다(2026-11-26 확인, 중국·한국 시차로 추정). **지금 한국 시각과 비교해 말이 되는 쪽**을 한국 게시 시각으로 쓴다.
   - 새 글이 여러 개면 모두 따라가고, 어느 글인지 모르면 묻는다.
2. `mcp__scheduled-tasks__create_scheduled_task`로 한 번짜리 예약(fireAt, `+09:00`) 8개를 만든다. 이미 지난 시각은 빼고 지금 바로 한 번 본다.
   - taskId: `xhs-track-MMDD-HHmm-1h` (…`-2h`, `-3h`, `-24h`, `-48h`, `-72h`, `-1w`, `-2w`)
   - 제목: `【게시글 분석】글 제목 앞부분 · 1시간`
   - 시킬 말(그대로 채워 넣기):
     `저장소 C:\Users\wjdwn\shaohong 에서 git pull 한 뒤 .claude/skills/post-tracking/SKILL.md 의 "예약 실행 때" 순서를 따른다. 글: "<중국어 제목>" / 게시 시각(한국): <YYYY-MM-DD HH:mm> / 이번 확인: <○시간>. 크리에이터 센터는 읽기만 하고, 답은 한국어로 강정준비준에게.`
3. **새 글의 첫 장(표지)을 저장한다** (2026-11-26 요청): 内容分析 표의 썸네일 이미지 주소(`?` 뒤는 떼고)를 받아 `샤오홍슈/분석/첫장/p<MMDD>-<HHmm>.jpg`(JPG)로 저장하고, 게시글 추적판에 `Artifact` publish `asset: true`로 올린 뒤 `data/team/posts/p<MMDD>-<HHmm>`의 `cover` 칸에 받은 `/_blob/…` 주소를 넣는다(`postedAt`·`name`·`posted`도 함께 만든다). 추적판은 글마다 카드 하나(첫 장 + 숫자 + 올린 뒤 변화)로 따로 보여 준다.
4. 8번의 날짜(요일)·시각을 짧게 알린다. 컴퓨터·Claude 앱·크롬이 켜져 있어야 하고, 꺼져 있으면 다시 켰을 때 늦게 실행된다고 알린다.

## 예약 실행 때
1. 内容分析 화면에서 그 글의 숫자를 읽는다: 曝光(노출) · 观看(조회) · 封面点击率(표지 클릭률) · 点赞(좋아요) · 评论(댓글) · 收藏(저장) · 涨粉(늘어난 팔로워) · 分享(공유) · 人均观看时长(평균 보는 시간). 거기에 아직 없으면 笔记管理 숫자만 적고 나머지는 비운다. **안 보이는 숫자는 만들지 않는다.**
2. 실제로 본 시각과 게시 후 실제 지난 시간을 적는다(늦게 실행됐으면 그대로 알린다).
3. `샤오홍슈/분석/게시글_추적.csv`에 한 줄 더하고 본 공책(main)에 합쳐 올린다.
   - **게시글 추적판**(https://claude.ai/artifact/KR5a67wiDABUVAqh9UfnKp, 2026-11-26)에도 `ArtifactData` set으로 한 줄 넣는다(페이지는 다시 발행하지 않는다). `data/team/checks`, 문서 id `p<MMDD>-<HHmm>-<1h|2h|3h|24h|48h|72h|1w|2w>`, 칸: `name`(짧은 한국어 글 이름) `point`("1시간"… "2주") `hours`(1·2·3·24·48·72·168·336) `posted` `postedAt`(YYYY-MM-DDTHH:mm) `seen`("11/27 (금) 10:00") `exposure` `views` `ctr` `likes` `saves` `comments` `shares` `follows` `watch` `note`. 같은 글의 `data/team/posts/p<MMDD>-<HHmm>`(`name` `posted` `postedAt` `seen`(YYYY-MM-DD)와 숫자 칸)도 최신 값으로 넣는다(있는 문서는 먼저 get 해서 if_version으로 update).
4. 짧게 알린다(쉬운 한국어):
   - 숫자 표: 이번 값 + 지난 확인보다 늘어난 만큼
   - 저장률(저장÷조회)·공유율·클릭률을 지난 글들의 **같은 시점** 값과 비교(없으면 비교할 기록이 아직 없다고 쓴다)
   - 읽은 것 1~2줄과 지금 할 일 1개. 근거가 데이터인지 크리링 추정인지 밝힌다. 숫자가 적은 초반에는 단정하지 않는다.
5. 2주 확인 때는 8번을 한눈에 정리하고, 찾은 개선점을 `post-draft` 스킬의 "결과에서 찾은 개선점"에 날짜와 함께 적고, 게시글 분석판(`analytics-board` 스킬)의 게시글 데이터에도 더한다.
